# AD3N1X Portfolio — Project Truth and Description Rules

The portfolio is the public index of the developer's work. It must describe both the intended product direction and the verified implementation without confusing one for the other.

## Description rules

1. Separate a product's **vision** from its **currently shipped capabilities**.
2. Use the linked repository and its current release notes as the source of truth for implementation claims.
3. Do not claim production readiness, user adoption, revenue, scale, certification or security guarantees without verifiable evidence.
4. Do not treat a successful deployment as proof that every workflow works.
5. Keep links consistent with each product's current canonical URL. Do not silently switch an app's canonical host until the production target has been verified.
6. Label clones and practice projects as independent recreations, not original products or official services.
7. Keep learning status accurate: current learning, completed study and planned technologies must remain separate.

## Selected project identities

### ADVERSE
**Vision:** An intent-to-action assistant that turns a complete objective into a guided, evidence-backed path, tracks progress and keeps consequential actions under user confirmation.

**Current documented baseline:** Intent understanding, bounded public-source discovery, destination checks, provenance, investigation/evidence workflows and reports. A full persistent step-by-step action workflow remains a release target and must not be implied complete.

### QuickCart
**Vision:** A Nigeria-first business and shopping platform that connects buyer journeys with a small-business operating system.

**Current documented baseline:** Storefronts, product catalogues, seller order workflows, customer checkout/tracking, WhatsApp handoff and an early set of Business OS modules. Several financial, procurement, delivery, marketing, AI-action and production-validation gates remain open.

### UNI-TRACK
**Vision:** A user-controlled productivity and tracking platform for goals, habits, tasks, activities and metrics.

**Current documented baseline:** Authentication, trackers, tracking views, export, push notifications and browser-side encryption utilities. User-facing private-key recovery/export is not yet verified on the current mainline.

### Cuewise
**Vision:** A careful conversation-reflection and reply-coaching tool that separates observable wording from assumptions and gives users editable, non-manipulative alternatives.

**Current documented baseline:** Screenshot text extraction, local rule-based analysis, optional consent-based remote AI and editable reply suggestions. AI output cannot establish another person's hidden feelings or intent.

## Portfolio release checks

- Verify all project links and preview targets before release.
- Keep project cards and case-study pages consistent.
- Confirm the same descriptions appear in README, `llms.txt`, page metadata and structured data.
- Identify outdated or conflicting links rather than silently guessing.
- Keep the original project repositories linked and avoid replacing them with new repositories.
